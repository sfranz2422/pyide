Tests — Check my work and Check all

A tests block in an assignment's notes is checked against the student's work. Students press Check my work as often as they like — on the tests' own card in the notes, where each test shows ✓ or ✗ and why. On the assignment's page, Check all runs what each student turned in, in your browser, and only that result is added to their grade. One test per line; each is 1 point unless the line ends with (2 points). Each kind of project has its own lines: a Python program is run, a web page is opened, a Flask app or a PHP site is asked for its pages.

In a Python program

```tests
input 3, 4 -> prints 12              run it, typing 3 then 4; the output must contain 12
input 5 -> prints exactly Area? 25    …or be exactly this (prompts included)
prints Hello                          run it with no input
area(3, 4) == 12        (2 points)    call their function and compare
uses for                              a for loop (also while, if, def, return, import math, len…)
avoids sum                            the name sum appears nowhere
defines area                          there is a def area
# a line starting with # is a comment
```

"prints" ignores capitals, extra spaces, single vs double quotes, and spaces around : , ; = and brackets — Stand:{"apples":3} passes prints Stand: {'apples': 3}. The words, numbers and their order still count; "prints exactly" counts everything. A program that runs longer than 5 seconds, or asks for more input than the test types, fails that test and says why.

On a web page (HTML / CSS / JS)

Checked against the page as a browser shows it.

```tests
has h1                                at least one h1 (has 3 li: at least three)
has exactly 2 img                     exactly two
h1 contains Welcome                   the first h1's text contains it
img has alt                           every img has an alt attribute
links to about.html                   a link going there
h1 color is red                       the style the browser shows
click #btn -> #out contains 1        click the first #btn, then check
logs Hello                            console.log printed it
uses addEventListener                 the JavaScript has that word (avoids: hasn't)
defines greet                         a function greet in the JavaScript
about.html: has h2       (2 points)   any line, on another page
#title color is blue                  an id works too: #title is a selector
# a comment: # and then a space
```

"contains" and "logs" ignore capitals and extra spaces. A page still busy after 8 seconds fails its checks and says why.

On a Flask app or a SQL project

Checked by asking the app for its pages, as a browser would; a SQL project, by running its queries.

```tests
GET / -> 200                              the page answers 200
GET /nope -> 404                          …or any other status
GET / contains Welcome                     the page shows Welcome
POST /login name=sam&pw=1 -> contains Hello, sam     a form sent to the route
uses render_template                       a name in the .py files (also for, if, import sqlite3…)
avoids eval                                the name eval appears nowhere
defines home        (2 points)             there is a def home
returns 3 rows                             SQL projects: the last query's rows
result contains Alice                      …and a value in them
# a line starting with # is a comment
```

"contains" ignores capitals and extra spaces, and looks at the page both as HTML and as a reader sees it. A route that crashes, or takes longer than 5 seconds, fails that test and says why.

On a PHP site

The same lines, with the pages' own addresses. Each check is one visitor: a log-in in one test is still logged in for the next, and a row one test adds is there for the next. uses, avoids and defines read the .php files the way PHP does, so a word in a comment, a string or the HTML never counts. A page that takes longer than 10 seconds fails its test. What PHP sites can do: PHP sites.

```tests
GET / -> 200                              index.php answers
GET /about.php contains Our club           a page shows the words
GET /game.php?id=2 contains Zelda          ?id=2 is $_GET['id']
POST /add.php title=Pong -> 302           a form that redirects…
POST /add.php title=Tetris -> contains Tetris    …and where it lands
uses foreach                               a keyword
uses $_SESSION                             a variable, spelled exactly
uses prepare                               a function or method, any case
avoids mysqli_query
defines add_game    (2 points)             there is a function add_game(...)
```

Slides

A line with only --- on it starts a new slide. A question can go on any slide.

Playing a slide a section at a time

Put animate: words as the notes' first line (beside theme:, either order), and students reading the notes get ▶ Play above them. Each press plays the next part of the slide, word by word — animate: type types it out letter by letter instead — and Play comes back when it's done, so a slide is read a piece at a time instead of all at once. A line with only ... on it divides a slide into the parts it's played in; a slide with none is played in one go. Too quick, or too slow? Add a speed: animate: words slow, animate: type fast, or just animate: slow. Without one it's normal. A ^ on its own — spaces round it, or a line to itself — pauses there for about a second before the rest comes in by itself (^^ waits twice as long); ... waits for the next press of Play. A ^ inside code is left alone. Wrap anything that should stand out — a sentence, a reminder, a code block — in :::pop and ::: lines: it arrives with a little pop, and stays in a highlighted box.

The next slide's arrow waits until the slide has been played. Slides already played show whole, so going back to look again replays nothing, and the notes reopen where the student got to. Your own previews play them too, with ⏭ Skip to get past a part, or a whole slide, while you edit, and ↺ Replay to watch a slide play again after you change it. A live lesson, the projector and the class pages never play them.

Holding students on a slide until its tests pass

Put locked: yes as a line at the top of the notes (beside theme: and animate:, in any order), and on a slide with a tests block the next slide waits until every test on it passes. Students press Check my work on the card and see which tests still fail; once they all pass, the arrow opens. A slide passed once stays open, even after a reload. A slide with a python predict example waits too, until the student's prediction is right, and a slide of flip cards waits until every card has been turned over. With animate:, a part holds ▶ Play the same way: put a small tests block right after a "Type this", and the next part waits until it's typed and passes. A wrong prediction never shows the output: each line is marked ✓ or ✗, and the next hint comes out. Hints are comment lines in the block, # hint: [0] is the first letter, hidden from the code. Right on the first try earns a little XP. A page can't be predicted by typing what it prints, so an html predict block with # choice: lines asks students to pick what it will show (# answer: names the right one); a wrong pick is marked ✗ with the next hint, and the page appears once they're right. Without the line, the tests still show and check in the notes, and students move through the slides freely. Your own previews are never held, and neither is a live lesson by this line: there every student stays on your slide while you're live, and moves when you do.

locked: yes
